Two files under `~/.shelbi/` hold hub-wide settings that apply across
every project on your machine, independent of any single project's
[config mode](/docs/concepts/config-modes): `config.yaml` (UI
preferences) and `keys.yaml` (keybindings). Both are optional: absent or
partial files fall back to built-in defaults, never an error.

<Callout type="note" title="Home resolution">

`~/.shelbi/` is the default base. It can be relocated via `--root`, then
`$SHELBI_ROOT`, then `$SHELBI_HOME`, then a default baked in at install time
(if any), before falling back to `$HOME/.shelbi`. Every path below joins a filename onto that base.

</Callout>

## `config.yaml`

Per-user UI preferences. Distinct from `shelbi.yaml` (the per-project
`last_launched` index) so a future `shelbi config reset` can wipe UI
tweaks without touching hub bookkeeping. A file that omits a key or a
block resolves to that setting's default.

A new install starts from a self-documenting `config.yaml` that sets
`theme: dark`, `desktop.contrast: 50`, and a translucent desktop window
(`desktop.window_opacity: 85` and `desktop.window_blur: 30`). Whichever
writes the file first (`shelbi init`, or a first settings change in either
client) writes those values, and with no file at all both clients show them.
An existing `config.yaml` is never rewritten: without these keys it keeps the
defaults in the tables below (`auto`, contrast `0`, an opaque window).

**Path:** `~/.shelbi/config.yaml`

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `keymap.zen_toggle` | [chord](#zen_toggle-chords) | no | `alt-z` | Legacy. Set the Zen Mode chord in `keys.yaml` (`defaults.global.zen_toggle`) instead: a non-default value here is moved into `keys.yaml` on the next start and reset here, with a one-time notice. |
| `theme` | `auto` \| `dark` \| `light` | no | `auto` | Color theme for the TUI and the desktop app. See [Theme](#theme). |
| `desktop` | [Desktop](#desktop) | no | — | Desktop app settings. Ignored by the CLI and the TUI (except `app_icon`, which the TUI's About draws). |
| `editor` | string | no | `$EDITOR`, else `vim` | Editor Shelbi opens for "Edit in `<editor>`" (in the [review interface](/docs/concepts/review-workspaces#the-review-editor) and the workspace panel) and for the desktop app's external edits (an issue body, a workflow's Edit YAML). Hub-wide, so it follows you across projects. May be a bare command (`hx`) or one with flags (`code --wait`). Resolution order: this key, then `$EDITOR`, then `vim`. |

```yaml
# ~/.shelbi/config.yaml
editor: code --wait
theme: light
desktop:
  contrast: 50
  window_opacity: 85
  window_blur: 30
```

The TUI's Settings ▸ General edits `editor` too: it shows the command Shelbi
runs and where it comes from (this key, `$EDITOR`, or the `vim` default), saves
what you type when you press Enter, and clearing it brings back the fallback.

The `editor` display label is the program's basename with its first letter
upper-cased: `hx` shows as **Edit in Hx**, `code --wait` as **Edit in Code**.

### Theme

`theme` picks the color theme both clients use. The two themes share one
set of named colors, so the TUI and the desktop app look like the same
product.

| Value | TUI | Desktop app |
| --- | --- | --- |
| `auto` (default) | dark (a terminal doesn't report whether it's light or dark) | follows the system appearance, and switches live when the system switches |
| `dark` | dark | dark |
| `light` | light, for a terminal with a light background | light |

Both clients set it in Settings ▸ General. In the TUI a change saves at
once and repaints every surface on the next frame, with no restart and no
effect on running sessions. The TUI also reads `config.yaml` again whenever
its Settings opens, so an edit made in a text editor or in the desktop app
shows there. A missing key is `auto` (a new install's file sets `dark`). The dark theme follows your terminal's own palette for
its status colors; the light theme pins every color, so it reads the same in
any light terminal.

### Desktop

The `desktop:` block holds the desktop app's settings. Its Settings ▸ General
and Settings ▸ Terminal pages write these keys for you; every one is optional.

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `cli_path` | path | discovered | The `shelbi` CLI the app runs, overriding its discovery (the login-shell `PATH`, then the Homebrew prefixes and `~/.cargo/bin`). A leading `~/` is expanded. |
| `terminal_font_family` | string | Geist Mono | Font family for the app's terminals. |
| `terminal_font_size` | integer (points) | app default | Font size for the app's terminals. |
| `option_as_meta` | `false` \| `true` \| `left` \| `right` | `false` | Whether Option acts as Meta in the terminals (Option+B sends `ESC b`) instead of typing the layout's Option characters. `left` / `right` make only that Option key Meta. |
| `terminal_scrollbar` | `auto` \| `scrolling` \| `always` | `auto` | When the terminals show a scrollbar: `auto` follows macOS's "Show scroll bars", `scrolling` only while scrolling, `always` whenever there is scrollback. |
| `notifications.workspace_blocked` | bool | `true` | Notify when a workspace's agent stops for you (waiting for input, or a permission dialog). |
| `notifications.review_ready` | bool | `true` | Notify when a task reaches the review column. |
| `notifications.orchestrator_waiting` | bool | `true` | Notify when the orchestrator waits for an answer or shows a permission dialog. |
| `terminal_colors.<color>.regular` / `.bold` | `#rrggbb` | theme palette | Terminal ANSI colors you changed, per color (`black`, `red`, `green`, `yellow`, `blue`, `magenta`, `cyan`, `white`). Unset colors follow the app's palette. |
| `window_opacity` | percent | `100` | Window opacity. Values below the floor of `30` are clamped up; a fraction like `0.85` reads as 85. A new install's file sets `85`. |
| `window_blur` | `0` to `50` | `0` | Blur radius, in points, for what shows through a translucent window. A new install's file sets `30`. |
| `contrast` | percent | `0` | How far apart surfaces and their text sit; `100` is the strongest step. A new install's file sets `50`. |
| `app_icon` | `command-grille` \| `retro` | `command-grille` | The icon in the Dock and in About. |

### `zen_toggle` chords

The accepted values for the Zen toggle chord:

| Value | Key |
| --- | --- |
| `alt-z` | Alt+Z (default) |
| `ctrl-backslash` | Ctrl+\ |
| `ctrl-g` | Ctrl+G |
| `ctrl-shift-z` | Ctrl+Shift+Z |
| `none` | disabled — no chord toggles Zen Mode |

## `keys.yaml`

Overrides for Shelbi's keybindings, shared by the TUI and the desktop app.
Both clients edit this file in Settings ▸ Keybindings (in the TUI press `,` in
the sidebar, then `2`; in the desktop app, ⌘2 while Settings is open). Built-in
chords apply out of the box;
this file layers on top of them, either globally (`defaults`) or per
project (`projects.<name>`). Parse errors never fail the load. A
mistyped entry is skipped and that action keeps its built-in chord.

**Path:** `~/.shelbi/keys.yaml`

### Shape

```yaml
# ~/.shelbi/keys.yaml
defaults:                 # applies to every project
  <mode>:
    <action>: <chord | [chords] | null>
projects:                 # per-project overrides, keyed by project name
  <project-name>:
    <mode>:
      <action>: <chord | [chords] | null>
```

Bindings resolve in three layers, each overriding the last: built-in
defaults → `defaults.<mode>.<action>` → `projects.<name>.<mode>.<action>`.

| Block | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `defaults` | map of mode → action → chord(s) | no | — | Overrides applied to every project. |
| `projects` | map of project name → (mode → action → chord(s)) | no | — | Overrides scoped to one project; win over `defaults`. |

### Leaf values

The value under each action is untyped so one bad entry only affects
itself:

| Form | Meaning |
| --- | --- |
| scalar string (`alt-z`) | Bind the action to a single chord. |
| list (`[k, up]`) | Bind the action to several chords. |
| `[]` (empty list) | Deliberately unbind the action. |
| `null` | No override — fall through to the layer below. |

### Modes

The valid top-level keys under `defaults` and each `projects.<name>`:

`global`, `sidebar`, `kanban`, `popover`, `activity`, `palette`.

`global` bindings apply everywhere; the rest scope to their pane.

### Actions

The action names accepted under each mode, with their built-in chords:

| Mode | Action | Built-in |

| `global` | `focus_sidebar` / `focus_main` | `ctrl-h` / `ctrl-l` |
| `sidebar` | `quit` | `q`,`ctrl-c` |
| `sidebar` | `nav_up` / `nav_down` | `k`,`up` / `j`,`down` |
| `sidebar` | `activate` | `enter`,`space` |
| `sidebar` | `refresh` | `r` |
| `sidebar` | `open_settings` | `','` (quoted: a bare comma isn't YAML) |
| `kanban` | `nav_left` / `nav_right` | `h`,`left` / `l`,`right` |
| `kanban` | `nav_up` / `nav_down` | `k`,`up` / `j`,`down` |
| `kanban` | `move_card_left` / `move_card_right` | `H` / `L` |
| `kanban` | `reorder_up` / `reorder_down` | `K`,`shift-up` / `J`,`shift-down` |
| `kanban` | `open_popover` | `enter`,`space` |

| `popover` | `scroll_up` / `scroll_down` | `k`,`up` / `j`,`down` |
| `popover` | `page_up` / `page_down` | `page-up`,`u` / `page-down`,`d` |

| `activity` | `scroll_end` | `G`,`end` |
| `activity` | `reset_filter` | `a` |
| `activity` | `toggle_zen_filter` | `z` |
| `activity` | `toggle_workspaces_filter` | `w` |

Most modes also carry `refresh` (`r`) and scroll-navigation actions
(`page_up`/`page_down`, `scroll_home`). For the full list with the chords in
effect after your `keys.yaml`, run
[`shelbi config list-actions`](/docs/cli/config#list-actions). `shelbi config
dump-keybindings` prints the whole default keymap as a starting `keys.yaml`, and
`shelbi config check` validates the file and reports errors and warnings.

A mode binding that reuses a `global` chord is dead in the `sidebar`, `kanban`,
and `activity` modes: global bindings fire first. `shelbi config check` warns
about it.

```yaml
# rebind the palette opener globally, and add a second chord in one project
defaults:
  global:
    open_palette: ctrl-k
projects:
  myapp:
    kanban:
      move_card_left: [H, alt-h]
```

## Sibling files

Two more files live under `~/.shelbi/` but are managed by Shelbi rather
than hand-edited:

- **`shelbi.yaml`** — hub-wide bookkeeping: a per-project `last_launched`
  index used by the project picker. Written when you launch a project.
- **`events.log`** — the cross-project [events log](/docs/concepts/events-log).
  Append-only state, not config.
