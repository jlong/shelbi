```text
shelbi wizard [OPTIONS]
```

`shelbi wizard` is the explicit interactive entry point for Shelbi's first
project setup. It walks the four steps every way of adding a project shares
(first-run `shelbi`, [`shelbi init`](/docs/cli/init), `shelbi project add`, the
TUI's **Add project** dialog and the desktop app's **Add Project** wizard),
each prompt starting on what Shelbi detected:

1. **Folder**: the repository (the top of the Git checkout you're in) and the
   project's name. A folder that isn't a Git repository gets an offer to run
   `git init -b <branch>`; a folder holding a teammate's committed
   `.shelbi/project.yaml` gets an offer to pick it up, which skips the other
   steps.
2. **Agents**: the default runner (the installed one preselected, Claude Code
   when both are) and model.
3. **Issues**: GitHub Issues or File system. GitHub is preselected, with the
   `owner/repo` pre-filled, when the origin remote is a GitHub repo, and is
   preflighted (`gh` installed and authenticated, Issues enabled, push access
   for labels) before setup moves on. On a failure Shelbi explains the fix and
   offers to retry or fall back to File system. See
   [`shelbi init`](/docs/cli/init#where-your-issues-live).
4. **Settings**: global (under `~/.shelbi/projects/`) or in-repo (committed at
   `<repo>/.shelbi/`), with Shelbi's recommendation and why.

Nothing is written until the last answer. Press Esc or Ctrl+C at any prompt to
leave without project state. Creating the project prints its progress, then
`✓ Project <name> created.`, and launches the dashboard.

Creating the project also installs a Shelbi `pre-commit` hook in the repo and
prints a one-time disclosure. The hook blocks commits to the default branch only
from Shelbi's agent sessions, never from your own shell, and it leaves a
user-authored hook untouched. Remove it with
[`shelbi guard uninstall`](/docs/cli/guard).

The command is idempotent at the project-registration level. If any project is
already registered, it exits quietly, without creating another one or opening
the dashboard. Use `shelbi project add` to run the same steps for an additional
project.

`wizard` honors the global `--root <PATH>` (the Shelbi state directory). The
global `-p` and `-y` flags parse but have no effect here: the wizard is always
interactive. For an unattended setup use [`shelbi init -y`](/docs/cli/init),
which takes every step's detected default.

## Examples

Run setup explicitly from the repository you want Shelbi to manage:

```bash
cd ~/code/myapp
shelbi wizard
```

For automation, accept every detected default instead:

```bash
shelbi init -y --runner codex
```
