The major, user-facing features Shelbi has grown, each with the date it landed
on `main`, newest first. This page is hand-curated: it tracks capabilities, not
every commit, so small copy edits and cosmetic tweaks are folded away. Entries
are prose with `code` and links where they earn their place.

### October 30, 2026

**v0.12.0. Settings and a launch screen in the TUI, a per-project Changelog, and tasks you edit in place.**

**A Changelog for every project.** Each project keeps a blog-style record of
what shipped. The orchestrator adds an entry after every merge, you read them on
the new Changelog page in both clients, and agents and scripts use
[`shelbi changelog`](/docs/cli/changelog) (`add`, `list`, `search`, `show`). The
sidebar nav is now Orchestrator, Issues and Changelog (🚀); Activity moves to the
command palette beside Machines ([#1962](https://github.com/jlong/shelbi/pull/1962), [#1995](https://github.com/jlong/shelbi/pull/1995)). See
[Changelog](/docs/concepts/changelog).

**A launch screen.** Run `shelbi` outside a registered project with no hub
daemon running and the TUI opens **Welcome to Shelbi**: the projects on this
Mac, your recent remote sessions, and **Add project** and **Connect to remote**
buttons ([#1985](https://github.com/jlong/shelbi/pull/1985)). `shelbi project add` still runs the detected setup card.

**Settings in the TUI.** The TUI gains the desktop's Settings over the same
shared models: General and Terminal, Keybindings, Workflows with the Form and
Builder editors, Agents, and Workspaces with the add and configure machine forms
and their readiness checks ([#1902](https://github.com/jlong/shelbi/pull/1902), [#1908](https://github.com/jlong/shelbi/pull/1908), [#1909](https://github.com/jlong/shelbi/pull/1909), [#1910](https://github.com/jlong/shelbi/pull/1910),
[#1911](https://github.com/jlong/shelbi/pull/1911), [#1913](https://github.com/jlong/shelbi/pull/1913), [#1915](https://github.com/jlong/shelbi/pull/1915), [#1916](https://github.com/jlong/shelbi/pull/1916), [#1917](https://github.com/jlong/shelbi/pull/1917), [#1920](https://github.com/jlong/shelbi/pull/1920),
[#1921](https://github.com/jlong/shelbi/pull/1921)). The sidebar footer gains Settings and Send Feedback buttons, with
About Shelbi, Acknowledgements and a Contact Us dialog to match the desktop
([#1933](https://github.com/jlong/shelbi/pull/1933), [#1934](https://github.com/jlong/shelbi/pull/1934), [#1938](https://github.com/jlong/shelbi/pull/1938), [#1940](https://github.com/jlong/shelbi/pull/1940), [#1958](https://github.com/jlong/shelbi/pull/1958)).

**Desktop.** Add Project becomes a wizard with a live creation checklist and a
workflow summary, after a first-launch check that installs the CLI if it's
missing ([#1876](https://github.com/jlong/shelbi/pull/1876), [#1898](https://github.com/jlong/shelbi/pull/1898), [#1900](https://github.com/jlong/shelbi/pull/1900), [#1903](https://github.com/jlong/shelbi/pull/1903)). Settings ▸ Workspaces
lists the pool and its machines, with dialogs to add and configure machines and
to create, edit and remove workspaces ([#1904](https://github.com/jlong/shelbi/pull/1904), [#1905](https://github.com/jlong/shelbi/pull/1905), [#1906](https://github.com/jlong/shelbi/pull/1906),
[#1914](https://github.com/jlong/shelbi/pull/1914)). The task detail becomes a floating task pane that shows the agent
working the task, and a task's title, body, status, workflow and priority edit
in place ([#1986](https://github.com/jlong/shelbi/pull/1986), [#1989](https://github.com/jlong/shelbi/pull/1989), [#1991](https://github.com/jlong/shelbi/pull/1991), [#1992](https://github.com/jlong/shelbi/pull/1992)).

**Shared boards.** On a GitHub Issues board, board search also asks GitHub
([#1984](https://github.com/jlong/shelbi/pull/1984)), and on a shared remote tracker Shelbi starts only the issues
assigned to you ([#1968](https://github.com/jlong/shelbi/pull/1968)).

**Polish.** In the TUI, the sidebar toolbar sits on the bottom row while Zen is
off, its Settings and Send Feedback buttons show no hover text, and toggling Zen
no longer prints a status line; the Zen band is the indicator
([#2001](https://github.com/jlong/shelbi/pull/2001), [#2004](https://github.com/jlong/shelbi/pull/2004), [#2007](https://github.com/jlong/shelbi/pull/2007)). Segmented controls no longer light up
on hover in either client ([#2012](https://github.com/jlong/shelbi/pull/2012)). On the desktop, picking an app icon no
longer shifts the tiles, the project menu is inset from the sidebar edges, and
Settings ▸ Shelbi CLI shows the binary in use, read-only, with a Reset for an
override ([#2003](https://github.com/jlong/shelbi/pull/2003), [#2009](https://github.com/jlong/shelbi/pull/2009), [#2013](https://github.com/jlong/shelbi/pull/2013)).

**Steadier dispatch.** A workspace left on an orphan branch with no
`.gitignore` (such as `docs/planning`) no longer refuses its next task over
ignored build output like `target/` ([#2020](https://github.com/jlong/shelbi/pull/2020)).

**Docs.** shelbi.dev's home page and docs gain a TUI | Desktop switch that swaps
every illustration, and in the docs the instructions too, for the client you
use ([#2018](https://github.com/jlong/shelbi/pull/2018), [#2022](https://github.com/jlong/shelbi/pull/2022)). The guides, concepts, configuration and CLI reference
were audited against the real app and corrected, with new pages for the
commands that had none ([#2021](https://github.com/jlong/shelbi/pull/2021)).

### October 23, 2026

**v0.11.0. The native macOS desktop app, plus steadier handoffs and sessions.**

**Shelbi has a native macOS app.** `Shelbi.app` is a second client beside the
TUI, built with gpui and at feature parity with it: both render the same models,
run the same command registry, and attach to the same daemon and sessions, so
the TUI, `shelbi attach` and the app can watch one agent byte for byte. On launch
the app finds the `shelbi` CLI, starts or adopts the daemon, and checks that the
versions match, offering a relaunch or an upgrade when they don't. A window shows
one project at a time and switches projects in place (`⌘⇧N` opens another), with
the sidebar, the Orchestrator chat, the Issues board with task detail and drag
and drop, Activity, Machines, the Workspace view (the agent with your own shell
beside it, local or remote), and the Review view (the task panel beside the
reviewer, with diff and editor sessions, approve and reject, and the review
server's live state). The command palette and the overlays (error log, add
project, load for review, reject reason, Zen intro) come along, as do native menus
that carry your `keys.yaml` chords and system notifications for a blocked
workspace, a task ready for review, or an orchestrator waiting on you. Terminals
are the app's own, drawn over Shelbi's shared emulator with scrollback,
selection, find, links and IME. Light and dark follow the system, and the TUI
gains the same light theme through a new `theme:` key (`auto`, `dark` or `light`)
in the global config ([#1683](https://github.com/jlong/shelbi/pull/1683)).

**Every view tuned for the desktop.** The Issues toolbar gains a search field
that narrows cards live by title, id and branch (`/` focuses it, Esc clears it)
([#1812](https://github.com/jlong/shelbi/pull/1812), [#1829](https://github.com/jlong/shelbi/pull/1829)). **More** in the Review and Workspace task panels opens
the full task detail over the screen you're on ([#1805](https://github.com/jlong/shelbi/pull/1805)). Activity paints at once
and scrolls at frame rate on thousands of rows ([#1818](https://github.com/jlong/shelbi/pull/1818)), and the sidebar slides
in and out instead of jumping ([#1814](https://github.com/jlong/shelbi/pull/1814)).

**Settings you edit in the app.** Settings (`⌘,`) gets its own sidebar in place
of the app's, with General, Keybindings and Terminal pages ([#1813](https://github.com/jlong/shelbi/pull/1813)). Keybindings
is a real editor: click a chord to rebind it, and the change is written to
`keys.yaml` with its comments kept and applies at once ([#1817](https://github.com/jlong/shelbi/pull/1817)). Terminal sets the
font and size, edits the ANSI colors against a live preview ([#1816](https://github.com/jlong/shelbi/pull/1816)), and picks
when the new macOS-style overlay scrollbar shows ([#1855](https://github.com/jlong/shelbi/pull/1855)). General adds window
transparency and a background blur behind it, stored as `desktop.window_opacity`
and `desktop.window_blur` ([#1820](https://github.com/jlong/shelbi/pull/1820)).

**Workflows and agents, editable in Settings.** Settings ▸ Workflows lists a
project's workflows and statuses ([#1826](https://github.com/jlong/shelbi/pull/1826)) and opens a workflow editor with two
views: a **Form** that edits statuses and transitions as rows ([#1828](https://github.com/jlong/shelbi/pull/1828)), and a
**Builder** that draws the workflow as a graph on a pannable, zoomable canvas,
with an inspector for each status and transition, connection handles you can
drag between statuses, and reorderable transition actions ([#1830](https://github.com/jlong/shelbi/pull/1830), [#1832](https://github.com/jlong/shelbi/pull/1832),
[#1834](https://github.com/jlong/shelbi/pull/1834), [#1841](https://github.com/jlong/shelbi/pull/1841), [#1842](https://github.com/jlong/shelbi/pull/1842)). **Edit YAML** in either workflow menu opens the file itself
for anything the editor can't express ([#1840](https://github.com/jlong/shelbi/pull/1840)). Settings ▸ Agents shows each
agent's preferred runner, the statuses that use it, and whether its files still
match what Shelbi ships, and an agent details page edits its name, description,
`instructions.md` and skills ([#1852](https://github.com/jlong/shelbi/pull/1852), [#1853](https://github.com/jlong/shelbi/pull/1853)). Both editors save through new
editing models in `shelbi-state` that patch the YAML in place, so the `##` help
blocks, comments and notes in your hand-edited files survive a save, and a
workflow that open issues still use can't be renamed or deleted out from under
them ([#1825](https://github.com/jlong/shelbi/pull/1825), [#1851](https://github.com/jlong/shelbi/pull/1851)).

**Installed with Homebrew, signed and notarized.** The release now builds,
signs, notarizes and staples `Shelbi.app`, attaches
`Shelbi-<version>-arm64.zip` to the GitHub release, and publishes it as the
`shelbi-desktop` cask in the Shelbi tap. The app is a client of the CLI, so the
cask depends on the `shelbi` formula; name both when you install
(`brew install jlong/shelbi/shelbi jlong/shelbi/shelbi-desktop`), and the app
tells you when a newer release is out. It needs an Apple silicon Mac on macOS 15
or later. It ships with the new Command Grille app icon ([#1683](https://github.com/jlong/shelbi/pull/1683), [#1845](https://github.com/jlong/shelbi/pull/1845)).

**The first release on Shelbi's own sessions.** This is the first tagged release
without tmux (see October 12 below), and the session runtime got a round of
hardening. A dead session is never read as live or classified from its final
frame ([#1663](https://github.com/jlong/shelbi/pull/1663)), a client never reattaches to a session that has already exited
([#1702](https://github.com/jlong/shelbi/pull/1702)), a resume prompt is delivered only into a live, ready session ([#1689](https://github.com/jlong/shelbi/pull/1689)),
and the supervisor really relaunches a dead orchestrator and logs `restart` only
once the new one is live ([#1690](https://github.com/jlong/shelbi/pull/1690)). `shelbi daemon stop` stops only its own root's
daemon, and a session's `exit.json` now records which signal ended it and who
sent it ([#1693](https://github.com/jlong/shelbi/pull/1693)). The daemon no longer idles out halfway through a quit ([#1742](https://github.com/jlong/shelbi/pull/1742)).
In the TUI, Switch Project now really switches: it rebuilds the views for the
target, starts its orchestrator, and paints the target at once instead of
freezing on the old project ([#1635](https://github.com/jlong/shelbi/pull/1635), [#1659](https://github.com/jlong/shelbi/pull/1659), [#1661](https://github.com/jlong/shelbi/pull/1661), [#1665](https://github.com/jlong/shelbi/pull/1665)), and the workspace header
reads the same status the sidebar shows ([#1660](https://github.com/jlong/shelbi/pull/1660)).

**Handoffs survive bounces and rewrites.** A task bounced back to a reused
workspace keeps its push provenance per branch, so the hub no longer refuses
the push of a tip it pushed itself, and a real block is raised to the
orchestrator once instead of looping quietly ([#1844](https://github.com/jlong/shelbi/pull/1844)). A worker that amends or
squashes an already-pushed commit no longer wedges its handoff, and a blocked
push heals itself once the branch is fixed ([#1643](https://github.com/jlong/shelbi/pull/1643)). A handoff force-push leases
against the fresh remote tip and caps its retries ([#1583](https://github.com/jlong/shelbi/pull/1583)), every move into the
handoff status detaches the worktree, not just the ready marker ([#1651](https://github.com/jlong/shelbi/pull/1651)), and a
stale merged PR can no longer finalize a reused branch ([#1627](https://github.com/jlong/shelbi/pull/1627)). Review slots load
the branch as a detached HEAD, so a branch checked out elsewhere never blocks a
review ([#1743](https://github.com/jlong/shelbi/pull/1743)).

**GitHub boards spend far less quota.** Idle TUI and daemon pollers read the
daemon's board index instead of sweeping the whole issue history, which had
emptied the REST quota about once an hour ([#1741](https://github.com/jlong/shelbi/pull/1741)). A rate-limit park only waits
for a window reset it can believe, and the `board rate-limited` event says
which limit tripped ([#1769](https://github.com/jlong/shelbi/pull/1769)). The Activity feed stops refetching done issues and
bounds its retries on a failing title fetch ([#1631](https://github.com/jlong/shelbi/pull/1631), [#1647](https://github.com/jlong/shelbi/pull/1647)), and `shelbi issue
start` right after a move no longer trips over its own write ([#1634](https://github.com/jlong/shelbi/pull/1634)).

**Per-worktree markers move to `.shelbi/`.** The ready, review-loaded,
push-blocked and transition markers now live in each worktree's `.shelbi/`
directory instead of `.claude/`, which is the runner's own config and not
Shelbi state. Update any script that watches the old paths ([#1609](https://github.com/jlong/shelbi/pull/1609), [#1611](https://github.com/jlong/shelbi/pull/1611)).

**Smaller fixes.** A worker's clarification question is stored on the hub in
full and attached to its event, instead of being cut at 120 characters ([#1703](https://github.com/jlong/shelbi/pull/1703)).
`shelbi zen ci-watch` waits for the commit's GitHub Actions run to exist before
calling it green ([#1655](https://github.com/jlong/shelbi/pull/1655)), and `shelbi zen probe` refuses a branch held by another
worktree before any local check runs ([#1649](https://github.com/jlong/shelbi/pull/1649)). Tracing goes to stderr, so
commands that print JSON keep their stdout clean ([#1653](https://github.com/jlong/shelbi/pull/1653)). The orchestrator's
shipped Reporting instructions name the issue, not the workspace, as the subject
of each update ([#1645](https://github.com/jlong/shelbi/pull/1645)), and the TUI palette hides workspaces until you type and
gives every action row an icon ([#1632](https://github.com/jlong/shelbi/pull/1632), [#1640](https://github.com/jlong/shelbi/pull/1640)).

### October 12, 2026

**Shelbi runs its own sessions; tmux is no longer required.** Each agent now
runs in its own Shelbi session, a small process that owns one PTY and outlives
the connection, instead of a tmux pane. Attach to any session from any terminal
with [`shelbi attach <workspace>`](/docs/cli/attach), rendered full-screen, and
detach with `Ctrl+]` without stopping the agent. The debug surface over sessions
is [`shelbi session`](/docs/cli/session) (`ls`, `new`, `kill`, `send`,
`snapshot`); remote machines are managed with
[`shelbi machine`](/docs/cli/machine) (`setup`, `status`) and reached through a
per-machine [`shelbi relay`](/docs/cli/relay). The deb and the Homebrew formula
drop their tmux dependency: beyond the `shelbi` binary itself, a machine needs
only `git` and your agent CLI, plus `ssh` to reach a remote one. The TUI is an
ordinary full-screen program, so it still runs fine nested
inside tmux or Screen if you prefer one. The retired tmux-era commands (`spawn`,
`archive`, `tail`, `merge`, `popup`, and `daemon install`/`uninstall`) are gone.

### October 5, 2026

**v0.10.0. A GitHub Issues board, optimistic kanban, and review-slot hardening.**

**Shelbi can run your board on GitHub Issues.** At onboarding you choose GitHub
Issues or the local file system as the issue tracker ([#1397](https://github.com/jlong/shelbi/pull/1397)), and a
GitHub-backed project reads and writes real issues instead of markdown files. The
daemon owns a `board-index.json` it refreshes incrementally over GraphQL, stamped
with the repo identity and a schema version and cold-read on a bounded interval,
so the TUI and sidebar read the board from a cache instead of blocking on the
network ([#1229](https://github.com/jlong/shelbi/pull/1229), [#1230](https://github.com/jlong/shelbi/pull/1230), [#1231](https://github.com/jlong/shelbi/pull/1231), [#1232](https://github.com/jlong/shelbi/pull/1232), [#1292](https://github.com/jlong/shelbi/pull/1292), [#1216](https://github.com/jlong/shelbi/pull/1216), [#1188](https://github.com/jlong/shelbi/pull/1188)). A single-issue read goes
through a REST conditional GET that spends from a request budget ([#1302](https://github.com/jlong/shelbi/pull/1302), [#1233](https://github.com/jlong/shelbi/pull/1233)),
every `gh` child runs under a deadline and is classified by HTTP status
([#1299](https://github.com/jlong/shelbi/pull/1299)), and a rate-limit or unreachable condition parks the backend and
honors the recorded reset time rather than hammering the API ([#1221](https://github.com/jlong/shelbi/pull/1221), [#1244](https://github.com/jlong/shelbi/pull/1244),
[#1321](https://github.com/jlong/shelbi/pull/1321)). A stale board read never triggers a destructive action. `shelbi
doctor` and `shelbi status` gained a GitHub section with staleness banners and a
points-based budget read, so you can see where your API quota is going
([#1235](https://github.com/jlong/shelbi/pull/1235), [#1403](https://github.com/jlong/shelbi/pull/1403)).

**Kanban moves are optimistic.** Dragging a card updates the board immediately and
persists in the background, so the UI stops waiting on a round-trip before it
redraws ([#1398](https://github.com/jlong/shelbi/pull/1398)). Press `o` on a card to jump straight to its assigned
workspace chat ([#1379](https://github.com/jlong/shelbi/pull/1379)).

**A persistent error log behind the sidebar.** View and backend errors that used
to scroll past now land in a per-project error log that survives a restart and
lights an unread-errors button in the sidebar, so a failure that happened while
you were away is still there when you look ([#1369](https://github.com/jlong/shelbi/pull/1369), [#1395](https://github.com/jlong/shelbi/pull/1395)).

**Review slots are steadier.** Tearing down a review slot now reaps the review
dev-server's whole process tree instead of leaking it ([#1399](https://github.com/jlong/shelbi/pull/1399)), and the reaper
never signals the caller's own process group ([#1485](https://github.com/jlong/shelbi/pull/1485)). A new
`review.diff_command` points the review diff at a revision-range tool of your
choice ([#1341](https://github.com/jlong/shelbi/pull/1341)), the shipped defaults allow a human-authorized rebase
([#1377](https://github.com/jlong/shelbi/pull/1377)), and review-slot ownership and occupancy are resolved from the
assignment overlay rather than a lagging board index, so selecting a serving slot
builds its panel instead of relaunching the agent ([#1349](https://github.com/jlong/shelbi/pull/1349), [#1376](https://github.com/jlong/shelbi/pull/1376), [#1373](https://github.com/jlong/shelbi/pull/1373),
[#1355](https://github.com/jlong/shelbi/pull/1355)).

**Agents can own custom active statuses.** A custom active board status is
auto-dispatched from the wake path ([#1306](https://github.com/jlong/shelbi/pull/1306)), categorized and re-dispatched by
its catalog identity ([#1305](https://github.com/jlong/shelbi/pull/1305)), and a parked gate is dispatched
deterministically ([#1312](https://github.com/jlong/shelbi/pull/1312)). A ready marker routes through an agent-owned
active gate before the handoff status ([#1309](https://github.com/jlong/shelbi/pull/1309)), and such a gate hands its
agent a reviewer prompt rather than the developer's ([#1311](https://github.com/jlong/shelbi/pull/1311)).

**Dispatch prompts carry the agent's charter inline.** The selected agent's
charter is inlined into the startup prompt as the authoritative instruction,
delivered exactly once and identically everywhere ([#1315](https://github.com/jlong/shelbi/pull/1315)).

**Zen probes are bounded and louder about failures.** The probe runs `cargo test`
with `--no-fail-fast` and keeps the failing-test output in the probe log
([#1483](https://github.com/jlong/shelbi/pull/1483)), every probe subprocess is bounded so a wedged child can't hang the
suite ([#1457](https://github.com/jlong/shelbi/pull/1457)), and a new `shelbi msrv-check` builds the workspace on the
declared minimum supported Rust version ([#1481](https://github.com/jlong/shelbi/pull/1481)). A `disk:` config block caps
the hub checkout's shared Rust `target/`, cleared before a probe builds, sweeps
leaked probe worktrees, and warns on `shelbi status` when free space drops below
the threshold ([#1493](https://github.com/jlong/shelbi/pull/1493)).

**Smaller fixes.** The poller refuses a ready handoff on an uncommitted or empty
branch ([#1507](https://github.com/jlong/shelbi/pull/1507)), a re-dispatch no longer tears down a busy prior assignee
([#1494](https://github.com/jlong/shelbi/pull/1494)), the poller detects a stalled agent inside a live pane ([#1325](https://github.com/jlong/shelbi/pull/1325)),
dispatch events are scoped to a single project and workspace ([#1381](https://github.com/jlong/shelbi/pull/1381), [#1339](https://github.com/jlong/shelbi/pull/1339)),
and the resume path answers the resume-from-summary dialog and recovers stranded
dev slots on reopen ([#1225](https://github.com/jlong/shelbi/pull/1225)).

### October 2, 2026

**Zen only auto-promotes GitHub issues assigned to you.** On a GitHub-backed
project, Zen Mode's mechanical scan now treats a backlog issue as eligible only
when it is assigned to the account Shelbi is authenticated as. Issues an outside
contributor opened, or that are assigned to someone else, no longer show up in
`shelbi zen scan` or the heartbeat's `zen_eligible` count, so Zen never
auto-promotes work you did not take on. The authenticated login is read from the
daemon's board index, so this adds no per-tick GitHub call, and if the login
cannot be resolved the scan returns nothing rather than guessing. To keep the
work Shelbi files eligible, any issue created through `shelbi issue add` or the
TUI new-issue flow on the GitHub backend is now assigned to you on creation.
Workspace routing (`assigned_to`) is unchanged and is still never written to
GitHub, and the filesystem backend is unaffected. Open issues Shelbi created
before this change are unassigned and will stop being auto-promoted; assign the
ones you want back with `gh issue edit <n> --add-assignee @me`.

### August 25, 2026

**v0.9.0. Multi-runner agents, plus review-slot and orchestrator hardening.**

**LLM configuration moved from the workspace to the agent, so you can mix and
match Codex and Claude per job.** An agent now carries its own `agent.yaml`
manifest, and a multi-runner resolution chain picks the runner and model from the
agent rather than the workspace it happens to land in ([#543](https://github.com/jlong/shelbi/pull/543)). A task or a board status can
override the launch for one dispatch ([#549](https://github.com/jlong/shelbi/pull/549)), and the reviewer is now
medium-agnostic so it runs the same whether the work under review came from Codex
or Claude ([#571](https://github.com/jlong/shelbi/pull/571)). The practical upshot: point a cheap fast runner at the
mechanical tasks and a stronger one at the hard ones, all on the same board.

**The orchestrator recovers from its own event drain.** The consuming event drain
is now deadline-aware and self-healing, so a stalled or wedged drain unblocks
itself instead of quietly starving the feed ([#580](https://github.com/jlong/shelbi/pull/580)). When a pane exits
unexpectedly, Shelbi captures a crash record (the exit code plus a tail of
`stderr`) so a worker that dies mid-task leaves evidence instead of a silent gap
([#560](https://github.com/jlong/shelbi/pull/560)).

**Config drift heals itself on boot.** A version-agnostic validate-and-upgrade
sniffer runs on start, flags config that has drifted from the current defaults,
and fixes what it safely can. Changes that need judgment are handed to the
orchestrator as findings rather than force-written, so your customizations survive
([#550](https://github.com/jlong/shelbi/pull/550), [#552](https://github.com/jlong/shelbi/pull/552), [#572](https://github.com/jlong/shelbi/pull/572)).

**The review flow stops fighting itself.** A hub-side merge is now idempotent, so
an already-integrated branch is treated as a success instead of an error
([#573](https://github.com/jlong/shelbi/pull/573)), and a PR that GitHub already merged counts as a merge success too
([#566](https://github.com/jlong/shelbi/pull/566)). The gated review-to-done merge fires at the move site so accepting a
review actually lands it ([#558](https://github.com/jlong/shelbi/pull/558)), loading a queued task onto a busy slot shows a
picker and evicts cleanly ([#564](https://github.com/jlong/shelbi/pull/564)), and a review window whose pane died

### August 5, 2026

**v0.7.2. Honest mid-flight comms and workflow-aware handoffs.**

**`shelbi message` tells the truth about delivery.** The command used to print a
checkmark and exit 0 the instant it wrote the durable record, conflating "queued"
with "the worker read it" — and on some hosts the ack never once landed (12 sent,
12 timeouts). Root cause: the worker's ack was gated behind `jq`, absent on stock
macOS and minimal Linux, so the ack block was silently skipped. Now the ack
extraction is `jq`-free and sends over `nc` (flavour-detected, `-N` on Linux) or a
`python3` fallback. The CLI stops over-promising too: a bare push prints
`queued … not yet confirmed delivered`, `--wait` blocks and exits non-zero on the
ack window elapsing, `shelbi message status <id>` reports the real outcome, and a
`done` task or dead pane is reported undeliverable rather than implying a future
pickup.

**Handoffs follow the workflow's base branch.** The workspace startup prompt
hardcoded `git rebase origin/main`, ignoring a task workflow's `git.base_branch`.
For fan-out workflows whose base isn't `main` (e.g. `feature/{{feature}}`), agents
that followed it produced wrong-base branches the merge guard rightly refuses. The
prompt now rebases onto the workflow's resolved base, mirroring the merge side so
the handoff and the merge target agree.

**Smaller fixes.** `task add`/`task edit` no longer hang reading stdin when the
body was already supplied by `--body`/`--body-file`/`-d`; the command palette hides
the redundant 'Switch Project' entry from its empty-query menu (it still surfaces
on typing); and the generated Homebrew formula drops the redundant `version`
stanza that `brew audit --strict` rejects.

**v0.7.1. Feature-branch fan-out you can trust.**

resolves that base from the task's frontmatter at every step instead of silently

### June 23, 2026

The first public cut of Shelbi: an open-source agent orchestrator for the
terminal, built on tmux. You talk to one orchestrator agent; it delegates work to
worker agents running in tmux panes, locally or over SSH, and reports back. This
landed the full local-to-remote loop end to end.

**Onboarding.** A first run with no projects drops you into a two-phase,
idempotent wizard that walks each project through setup. It auto-fills from your
environment (repo path, default branch, GitHub URL) and suggests a worker count
from available RAM. `shelbi` with no arguments launches the sole project's TUI,
or a fuzzy picker when there's more than one.

**The TUI.** A two-pane ratatui dashboard: a sidebar with Chat/Tasks
navigation, a live worker roster with state badges (working, awaiting input,
awaiting permission, review-ready, idle), and a `Ready for Review` queue;
beside it a content pane that swaps between the orchestrator chat, a five-column
Kanban (Backlog → Todo → In Progress → Review → Done), a Machines view, and a
Review list. `Ctrl+P` opens a Nucleo-backed fuzzy command palette as a tmux
popup for jumping between projects, workers, and views.

**Orchestration.** Move a card to Todo and the orchestrator takes it from
there. It watches the column and, as soon as a worker frees up, checks out the
highest-priority unblocked card on a fresh branch in that worker's own
worktree and starts the runner. `depends_on` blocks a task until its
dependencies land in Done. Finished work lands in Review and the worker stops;
activating a review checks the branch out, spawns a fresh agent pane to
interrogate the diff, and lets you merge into the default branch, or push and
open a PR with `--pr`.

**Anywhere tmux runs.** Workers run on the hub or on any machine reachable over
SSH with `tmux` and an agent CLI installed. Shelbi drives panes with
`tmux send-keys` + `capture-pane`, transparently prefixed with `ssh host --`
for remotes; a poller reads each pane's `shelbi:<state>` title marker into
worker status, which is what lights up the sidebar badges. Agent runners
(`claude`, `codex`, or any interactive CLI) are pluggable and declared
per project.

**State you can read.** No daemons, no servers, no database: every project,
task, log, and worker status is a markdown or YAML file under `~/.shelbi/`.
The same `shelbi` CLI the orchestrator drives (`task`, `merge`, `reload`,
`events`, …) is the one you can run yourself.

**The website and docs.** A Next.js marketing site and a contentlayer-backed
MDX documentation set (Getting Started, Concepts, and a CLI reference for every
`shelbi` subcommand) ship alongside the release.

Install from source with `./scripts/install.sh` (builds `--release`, drops the
binary at `$HOME/bin/shelbi`, ad-hoc re-signs on macOS).
