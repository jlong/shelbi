## Executive summary

30 findings across the seven pages: **0 critical, 7 high, 12 medium, 11 low**.

The single most important result is a **negative** one relative to the prior
audit: the 2026-07-13 **critical** finding (C1 — the three-way inconsistency
between the documented review-workspace contract, the shipped Reviewer prompt,
and the loader/transition implementation) is **no longer present in the concept
docs**. `review-workspaces.mdx` has been rewritten to the current model: tag
routing, the `review:` serve block executed by the Review agent, no
`shelbi workspace serve`, no `review.setup`/`review.serve` fields, and the
finishing dev workspace closing its own pane. The current review page is the
most accurate of the seven (details under Review workspaces below).

The two areas the task flagged for special attention split cleanly:

- **Review-workspace lifecycle: docs match current reality.** The dev workspace
  self-closes on handoff, review load is a distinct step, and there is no
  `shelbi review` command — all confirmed against source. The only residual
  drift is that review loading is now **also** automated by the daemon
  (`autoload_review_queue`), which two pages still describe as a human-only
  sidebar action.

- **Events log + heartbeat unification (#521): docs are stale.** The retired
  keepalive and adaptive/back-off heartbeat narrative made it into
  `events-log.mdx`, but the **record grammar itself was never updated**. Every
  documented line shape omits the load-bearing `project=<name>` scope; task
  lines additionally omit `workflow=` and the `from_category=`/`to_category=`
  annotations the orchestrator now pattern-matches on; and the heartbeat cadence
  defaults are wrong (docs say 3m / 60m cap / "once an hour"; code is 60s / 5m
  cap). This is the same class of error the prior audit filed as H2 — still open.

A cross-cutting wire-token error recurs on three pages: `worker=<name>` is
documented as the workspace event prefix, but no emitter has written `worker=`
since the rename to `workspace=` (`events-log.mdx` uses the correct token in
some places, `workspaces.mdx` and `orchestrator.mdx` use the stale one).

## events-log.mdx

The heartbeat *feature* narrative was added, but the *record grammar* — the
whole reason this page exists — predates the `project=`-scoped, category-enriched
records and still names retired symbols.

### EV-1 — Line grammar omits the `project=` scope (and task enrichment)
- **Severity:** High — confirmed-error
- **Doc:** `events-log.mdx:32-40` (workspace shape + examples), `:51-59` (task
  shape + examples), `:162-166` (the "five-line burst"), `:213-217` ("Reading
  the log from code" contract).
- **Doc claim:** workspace lines are `workspace=<name> <prev-state> -> <new-state>`;
  task lines are `task=<id> <from-column> -> <to-column> reason=<short>`.
- **Source:** `crates/shelbi-state/src/event_log.rs:723-724` —
  `"{ts} project={project} workspace={workspace} {prev_str} -> {new}"`; the
  docstring at `:702-712` calls the leading `project=<name>` scope "load-bearing"
  (the log is hub-global; each orchestrator filters to its own project). Task
  lines: `event_log.rs:979` docstring and `task_event_body` (~`:1106-1128`),
  `append_task_event` at `:995` —
  `project=<p> task=<id> workflow=<name> <from> -> <to> reason=<short> from_category=<cat> to_category=<cat>`.
- **Assessment:** Every documented example is missing `project=`; task lines are
  additionally missing `workflow=`, `from_category=`, and `to_category=`. An
  external consumer built from this grammar misparses every current line. Same
  root cause as WS-1 and OR-1.

### EV-2 — Heartbeat cadence defaults are wrong (3m/60m/"once an hour")
- **Severity:** High — confirmed-error
- **Doc:** `events-log.mdx:84-89`.
- **Doc claim:** "the poller holds at the standard `interval` (default `3m`)…
  doubling each idle tick and capping at `max` (default `60m`). A fully idle hub
  relaxes `3m → 6m → 12m → … → 60m`, so even a long-quiet board still sweeps for
  a silently-stuck task about once an hour."
- **Source:** `crates/shelbi-core/src/model.rs:310` —
  `HEARTBEAT_DEFAULT = Duration::from_secs(60)`; `:316` —
  `HEARTBEAT_MAX_DEFAULT = Duration::from_secs(300)` (5m). Scaffold agrees:
  `crates/shelbi-core/src/scaffold.rs:169-175` ("Defaults: interval 60s, max
  5m"). The adaptive-back-off state machine is `maybe_emit_heartbeat`
  (`crates/shelbi-tui/src/poller.rs:495-513`).
- **Assessment:** Both defaults are wrong and the derived narrative is materially
  misleading about a safety mechanism: a fully idle board relaxes
  `60s → 2m → 4m → 5m` (capped), sweeping roughly every 5 minutes, not once an
  hour. `3m` appears in code only as an example duration string in a doc comment
  (`model.rs` ~`:329`), the likely source of the mistake. Shared with ZM-2.

### EV-3 — Heartbeat line shape omits the trailing count tokens
- **Severity:** Medium — confirmed-error
- **Doc:** `events-log.mdx:69-76`.
- **Doc claim:** `<rfc3339-timestamp> project=<name> heartbeat` (and the example
  `2026-06-22T14:25:11+00:00 project=myapp heartbeat`).
- **Source:** `crates/shelbi-state/src/event_log.rs:1345-1358` (`append_heartbeat_event`) —

  `project=myapp heartbeat zen_eligible=5 idle_workspaces=4`.
- **Assessment:** The heartbeat line always carries `zen_eligible=` and
  `idle_workspaces=` (plus a `zen=on` marker when Zen is on); the documented
  shape and example drop all of them.

### EV-5 — "Second token" positional distinguisher is wrong
- **Severity:** Medium — drift-risk
- **Doc:** `events-log.mdx:118-123` ("distinguishes the line kinds by the second
  token (`task=`, `workspace=`, `project=`, `dispatch`, `mode=zen`,
  `zen-dryrun`)"), `:215-217` ("Two prefixes (`workspace=` or `task=`) keyed off
  the second whitespace-separated token after the timestamp").
- **Source:** classification is `EventKind::from_body`
  (`crates/shelbi-state/src/event_log.rs:111-154`), which uses `contains`, not a
  positional token. With the `project=` scope now leading every state line, the
  token after the timestamp is `project=`; `workspace=`/`task=` are the *third*
  token. The listed discriminators still exist (`dispatch ` `:138`, `mode=zen `
  `:142`, `zen-dryrun ` `:144`) but the family also includes `ci`, `message=`,
  `question=`, `pane_alive=`, `supervision=`, `rebase`, `integration`, `send`.
- **Assessment:** The positional "second token" contract is no longer true; a
  parser written to it keys off the project name. The page does hedge ("consumers
  that only recognize `task=` and `workspace=` should fall through gracefully"),
  which softens this to drift rather than a hard contradiction.

**Verified accurate on this page:** the connectivity-pause behavior
(`1.1.1.1:443`, 1s timeout — `poller.rs:750-761`); crash-safe first-attempt-one-
interval-out and reset-on-real-event (`poller.rs:480-513`); atomicity via
`O_APPEND` ≤ `PIPE_BUF` (4096); `shelbi events tail` flags `-n` (default 20),
`--since`, `--follow` (`commands/events.rs` help) and the 250ms follow poll with
fragment holdback and truncation-restart (`commands/events.rs:105-134`); the
`reason=` convention tokens (`workspace:ready-marker` =
`READY_MARKER_HANDOFF_CAUSE` at `event_log.rs:165`; `orchestrator:auto-dispatch

mention the `--format envelope` machine-readable output (an omission, not an
