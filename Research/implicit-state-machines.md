# Implicit state machines in Shelbi

Audit of the Shelbi codebase (origin/main at b93c57c4) on 2026-11-05.

## Orchestrator's assessment

Most of the 71 "needs further thought" machines are medium-severity design debt. The ones below are different: verified, live bugs, several of which explain problems seen while running this hub. They are where I'd start.

**Live bugs we have already felt**

1. **Worker messages after the first drain never arrive** (sessions/panes, "Worker message delivery, ack and clarification questions"). The message tail writes into an `unread.log` inode the Stop hook renames and unlinks, so later `shelbi message` pushes go to a deleted file. This is why mid-task directives "ack-timeout and often aren't incorporated". `crates/shelbi-orchestrator/src/workspace.rs:4569, 4618-4670`.
2. **Review content sessions outlive the decision and get reused** (review/merge, "Review slot serving lifecycle"). Editor and diff sessions are keyed by slot, not task, and are not closed after a decision, so the next review on that slot can show the previous task's diff. Likely part of the "diff doesn't load the first time" reports. `crates/shelbi-tui/src/shell/mod.rs:4643-4652`, `crates/shelbi-orchestrator/src/review_session.rs:405-410`.
3. **events.log rotation has been blocked since Sep 4** (daemon/process). Any stale per-project event cursor below the current base keeps the previous generation alive forever; nothing ages cursors out. events.log is over its 8 MiB limit on this hub. `crates/shelbi-state/src/event_log.rs:3335-3369`.
4. **Crash-vs-deliberate exit detection is unwired** (sessions/panes, two clusters). Since the tmux removal (90960807) nothing writes the supervisor's no-restart key, so a worker that exits cleanly with a task assigned is treated as a crash and restarted. `crates/shelbi-orchestrator/src/poller.rs:4735`.
5. **SSH "health check" tears down a healthy ControlMaster every run** (remote/SSH). `drop_master` runs before any probe, once per workspace thread, killing multiplexed relay channels and in-flight git commands on that host. `crates/shelbi-ssh/src/lib.rs:1344-1351, 1521, 1619`.
6. **Zen's user-demotion latch is dead** (review/merge). The parser expects ` todo -> backlog` right after the task id, but the writer puts ` workflow=...` in between, so Zen can re-promote a card the user just demoted. `crates/shelbi-orchestrator/src/zen.rs:14518-14523`.

**Correctness risks to schedule**

- **Workspace slot occupancy is derived three ways** (task lifecycle). A gate dispatch kills the previous assignee's pane without the busy check `issue start` does, and the dispatch guard treats only the literal `in-progress` status as occupying a slot, so custom active gates can be double-booked.
- **Daemon shutdown abandons control-socket jobs** (daemon/process). Mutations, merges and state writes run on untracked threads that die mid-way when the daemon exits. The lost-login-session re-exec also races its own bind lock and usually leaves no daemon.
- **A transient GitHub read failure drops a gate verdict** (task lifecycle, "Agent transition marker"). A 403 or network error while loading the task clears a one-shot pass/reject marker.
- **Zen merge lands without the pinned head** (review/merge). The `review -> done` merge action calls `gh pr merge` with no `--match-head-commit`, so the probe/CI identity Zen checked is not enforced at merge time.
- **Hub-global workspace status files collide across projects** (sessions/panes). `status.yaml` and teardown markers are keyed by workspace name only, but names are unique only within a project.
- **Quit leaves the quitting project's remote sessions running** (daemon/process), **`handoff.md` is consumed by every `ensure_dashboard`** (sessions/panes), **the VT responder can wedge on an ESC-interrupted OSC** (sessions/panes), **the TUI's done-column "load more" can't get past page 2** (shared app model), **a project switch mid-move freezes that issue's save lane** (shared app model), and **remote-window notifications switch to a bogus `host:proj` project** (desktop).

**Structural theme.** The task status lifecycle has two move implementations (`move_issue` and `approve_review_task`) that have already drifted, three copies of the dispatch-target rule, and a display-only `Column::category` fallback that still drives Zen reconcile. Making that one explicit transition path would remove a whole family of the medium findings.


## Definition

An implicit state machine is anything with a lifecycle (it moves between discrete states over time) where the states or the legal moves between them are not captured by one explicit type plus one transition function. In this codebase that shows up as combinations of bools, Options, timestamps and counters that together mean a state; status strings compared in many places; explicit enums whose transitions are scattered across modules; marker files, lock files, stamps, state.json keys and events.log line sequences; retry, backoff, timeout and in-flight flags; and UI modes driven by loose flags.

## Method

- 26 parallel readers each covered one slice of the code: 24 slices for all 615 Rust files, one for scripts, the site, GitHub workflows and shipped workflow YAML, and one cross-cutting pass for state that lives outside Rust types (marker files, state.json, events.log).
- They reported 328 candidates. A clustering pass merged reports of the same lifecycle seen from different crates (daemon, TUI, desktop) into 122 machines and dropped 11 trivial ones.
- One evaluator per machine read the cited code, tried to refute every concern, and kept only what the code supports. Each machine got a verdict: needs further thought (71), worth tidying (38), fine as is (13).
- Severity on concerns is the evaluator's. Line numbers are against b93c57c4 and will drift.
